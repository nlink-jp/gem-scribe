# ADR-0001: 文字起こしは構造化 ASR 応答から取る（LLM に JSON を書かせない）

> Status: Accepted
> Date: 2026-08-30

## 背景

前身の gem-transcribe は、汎用 Gemini モデルに音声の文字起こしをさせ、セグメントの
JSON ドキュメントとして返させていた。長尺音声ではモデルが壊れた JSON を出力し、
処理が停止した。v0.2.1 では 2 つの緩和策を入れている — 解析に失敗したセグメントを
落とす per-segment サルベージと、生成を制約する `response_schema`。その後どうなったかは
リリースノートに残っている。**response_schema を入れても malformed JSON は発生し得た**、
修復はたいてい成功した、そして当時の結論は「予防は保証ではない」だった。

その結論は正しい。そして同時に、このアーキテクチャの行き止まりでもある。どの緩和策も
「モデルが自由記述した文書を耐え忍ぶ」方法であって、文書を正しくはしない。しかも
サルベージは、内容を黙って捨てることで生存を買っている — 会議の 40 秒を失った
文字起こしと、失っていない文字起こしは、カウンタ以外は呼び出し側から同じに見える。

Vertex AI は現在、文字起こし専用モデル `gemini-3.5-transcribe-preview` を提供している。

## 決定

文字起こしはモデルの構造化応答から取る。**構造をモデルに書かせることは、どのモデルに
対しても行わない。**

文字起こし専用モデルは、話者ターンごとに独立した応答パートを返す:

```
parts[].audioTranscription: { text, speakerLabel, words[]{word, startOffset, endOffset} }
```

出力エンベロープへの写像は機械的で（`speakerLabel` → `speaker`、words の最初と最後の
オフセット → `start` / `end`）、純粋関数（`asr.Parse`）として実装し、記録した実応答に
対してテストする。

結果として gem-scribe には、プロンプト層も response schema も JSON 修復も
サルベージも存在しない。それらがやる仕事が無い。

## 影響

**破綻モードは緩和ではなく消滅した。** 31 分の録音は 209 パートとして返り、話者ラベルは
一貫し、タイムスタンプは音声の末尾まで到達した。より長い録音が構造的に不正な文字起こしを
生む経路は存在しない。構造がモデルの書くものではないからである。

**`metadata.dropped_segments` は互換フィールドとして残り、常に 0。** 共有エンベロープに
存在するのは gem-transcribe が必要としたからで、削除すると 3 ツールを想定して書かれた
消費側が壊れる。ここでは何もこれを増やさない。

**2 つの機能は汎用モデル側に残った。** 専用モデルは翻訳しない（日本語音声に
`languageCodes: ["en-US"]` を与えても日本語のまま。このフィールドは検出ヒントである）し、
話者は `spk:0` であって実名ではない。どちらも**転写テキストに対する第2パス**へ移す。
入力が数時間の音声ではなく有界なテキストになり、不要ならまるごとスキップできる。
かつて失敗していたのと同じ種類の仕事だが、はるかに小さい入力に対して、失敗しても
文字起こし本体ではなく付加情報だけを失う経路で行う。

**新しい種類の「静かな誤り」が現れ、それには別の答えが要る。** 似た2つの声の分離に
失敗したとき、モデルは完全に妥当な文字起こしを返す。3名以上の話者帰属は
ドキュメント上 experimental とされている。**構造的な妥当性が内容の正しさを意味しなく
なった**ため、`transcript.Diagnose` がこれらの形に名前を付け、MCP の結果は `warning`
として運ぶ。エージェントは音声を聴けない。このフィールドが無ければ、良い文字起こしと
自信ありげな誤りを区別する手段が無い。

## 検討した代替案

**gem-transcribe を残し、LLM 層だけを差し替える。** 妥当ではあった — データモデルと
フォーマッタは生き残る。却下したのは、MCP サーバ・ジョブモデル・共有エンベロープを
すでに備えた voice-scribe の実証済み骨格から起こすほうが、いずれ死にコードになる
プロンプト層・スキーマ層・サルベージ層を引き継ぐより良いため。

**専門用語のために `customVocabulary` を使う。** 却下。指定すると文字起こしが最初の
1 ターンで打ち切られ、しかも `finishReason: STOP` を返す挙動が実測で毎回再現した。
内容の大半を黙って捨てる機能は、無い機能より悪い。
